# 🚨 Detection & Investigation

This document contains the Wazuh detection queries, filters, and investigation searches used to analyze security telemetry in the lab.

---

## 1. Wazuh Alerts

The main Wazuh alert index is:

```text
wazuh-alerts-*
```

Basic alert search:

```text
*
```

Filter alerts generated by the Windows endpoint:

```text
agent.id:001
```

Filter high and critical alerts:

```text
rule.level >= 10
```

---

## 2. OpenCanary Detection

OpenCanary events are identified using the OpenCanary rule group.

### All OpenCanary alerts

```text
rule.groups:opencanary
```

### OpenCanary HTTP activity

```text
rule.description:"OpenCanary: HTTP connection detected"
```

### OpenCanary SSH activity

```text
rule.description:"OpenCanary: SSH connection detected"
```

### OpenCanary FTP activity

```text
rule.description:"OpenCanary: FTP login attempt detected"
```

### OpenCanary Telnet activity

```text
rule.description:"OpenCanary: Telnet connection detected"
```

These queries allow individual honeypot services to be investigated separately.

---

## 3. OpenCanary Rule IDs

The verified custom OpenCanary detections include:

| Rule ID | Detection |
|---:|---|
| `100501` | OpenCanary SSH connection |
| `100502` | OpenCanary FTP login attempt |
| `100503` | OpenCanary Telnet connection |

The HTTP detection was also verified through its alert description.

## 4. Windows Security Events

Windows endpoint activity can be filtered using:

```text
agent.id:001
```

### Successful logon

```text
agent.id:001 AND data.win.system.eventID:4624
```

### Failed logon

```text
agent.id:001 AND data.win.system.eventID:4625
```

These searches can be used to investigate authentication activity on the Windows endpoint.

## 5. Sysmon Investigation

Sysmon events are available in the Wazuh Archives index:

```text
wazuh-archives-*
```

### All Sysmon events

```text
agent.id:001 AND data.win.system.providerName:"Microsoft-Windows-Sysmon"
```

### Sysmon Event ID 3 — Network Connection

```text
agent.id:001 AND data.win.system.eventID:3
```

Event ID 3 can be used to investigate network connections generated by processes on the Windows endpoint.

### Sysmon Event ID 22 — DNS Query

```text
agent.id:001 AND data.win.system.eventID:22
```

Event ID 22 can be used to investigate DNS queries generated on the endpoint.

### Specific Sysmon provider and event

```text
agent.id:001 AND data.win.system.providerName:"Microsoft-Windows-Sysmon" AND data.win.system.eventID:3
```

## 6. PowerShell Investigation

PowerShell telemetry is collected from:

```text
Microsoft-Windows-PowerShell/Operational
```

### All PowerShell events

```text
agent.id:001 AND data.win.system.channel:"Microsoft-Windows-PowerShell/Operational"
```

### PowerShell Script Block Logging

Event ID `4104` is used to identify PowerShell script block activity.

```text
agent.id:001 AND data.win.system.eventID:4104
```

For investigation, the event can be examined for fields such as:

- `scriptBlockText`
- Event timestamp
- User/account information
- Host information
- Related PowerShell events

## 7. File Integrity Monitoring

FIM events are identified using the Wazuh `syscheck` rule group.

### All FIM activity

```text
agent.id:001 AND rule.groups:syscheck
```

### Modified files

```text
agent.id:001 AND rule.groups:syscheck AND syscheck.event:modified
```

### Added files

```text
agent.id:001 AND rule.groups:syscheck AND syscheck.event:added
```

### Deleted files

```text
agent.id:001 AND rule.groups:syscheck AND syscheck.event:deleted
```

Useful fields for investigation include:

```text
syscheck.event
syscheck.path
syscheck.mode
syscheck.md5_after
syscheck.sha1_after
syscheck.sha256_after
```

## 11. Detection Investigation Workflow

A useful investigation sequence is:

```text
Start with Alert
      ↓
Identify Agent / Source
      ↓
Identify Rule or Event ID
      ↓
Search Wazuh Archives
      ↓
Search Related Telemetry
      ↓
Review Timestamp
      ↓
Correlate Events
      ↓
Determine Activity Context
```

For example, a Windows investigation can move from:

```text
PowerShell Event 4104
        ↓
Sysmon Event 1 / 3 / 22
        ↓
FIM Activity
        ↓
Windows Security Events
        ↓
Defender Events
```

This allows multiple telemetry sources to be examined together instead of relying on a single event.

## 13. Dashboard Investigation

The SOC dashboard provides saved visualizations for quickly identifying activity across the environment.

The dashboard can be narrowed using DQL filters such as:

```text
agent.id:001
```

```text
rule.groups:opencanary
```

```text
rule.level >= 10
```

These filters allow an analyst to move from an overall SOC view to a specific endpoint, detection category, or severity level.

---

## 14. Important Field References

Common fields used during investigation include:

| Field | Purpose |
|---|---|
| `agent.id` | Identifies the Wazuh agent |
| `rule.id` | Identifies the matched Wazuh rule |
| `rule.level` | Alert severity level |
| `rule.description` | Detection description |
| `rule.groups` | Detection category |
| `data.win.system.eventID` | Windows/Sysmon event ID |
| `data.win.system.channel` | Windows event channel |
| `data.win.system.providerName` | Event provider |
| `syscheck.event` | FIM event type |
| `syscheck.path` | Affected file/path |
| `timestamp` | Event time |

## 🔐 Notes

The queries documented here correspond to telemetry and detections implemented in this lab.
